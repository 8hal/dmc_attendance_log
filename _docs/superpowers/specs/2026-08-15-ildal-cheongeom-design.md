# 일달천금 — 설계 스펙

**작성일:** 2026-08-15  
**프로젝트:** 일달천금 (천원길도 1킬로부터)  
**요약:** 친구 7명이 1km 달릴 때마다 스폰서가 1,000원 지급하는 러닝 보상 웹앱. 자본금 100만원이 소진될 때까지 운영.

---

## 1. 프로젝트 개요

### 배경
- 스폰서(문광명)가 러너 친구 7명에게 1km 달릴 때마다 1,000원 지급
- 자본금 100만원 한도 내에서 운영, 소진 시 종료
- 전년도 유사 프로젝트 경험 있음 (계약서 기반 운영)
- 속도 기준: 1km를 7분~10분대 내 완주

### 목표
- 러너들의 달리기 동기 부여
- 투명한 기록 관리 및 리더보드를 통한 경쟁
- 스폰서의 승인·정산 작업 최소화

---

## 2. 사용자 및 역할

| 역할 | 설명 | 인증 방식 |
|------|------|-----------|
| **러너** | 달리기 기록을 제출하고 보상을 받는 친구 7명 | 이름 선택 (로그인 없음) |
| **스폰서(관리자)** | 기록 승인, 송금 처리, 잔액 관리 | 비밀번호 입력 |

---

## 3. 화면 구성

### 3-1. 홈 / 리더보드 (`/`)
- 자본금 잔액 표시 (100만원 중 얼마 남았는지)
- 러너별 순위: 총 획득 금액 기준 내림차순
- 각 러너 항목: 이름, 총 km, 총 획득 금액
- 로그인 불필요, 누구나 접근 가능

### 3-2. 기록 제출 (`/submit`)
1. 이름 목록에서 본인 선택 (드롭다운)
2. 러닝 앱 스크린샷 업로드
3. GPT-4o Vision이 이미지에서 거리(km)·시간(분:초)·페이스 자동 추출
4. 추출 결과 화면에 표시, 러너가 확인 후 제출
5. 추출 실패 시 수동 입력 fallback 제공
6. 제출 후 "승인 대기" 상태로 전환

### 3-3. 내 기록 (`/records/[runnerId]`)
- URL 키는 러너 `id` 사용 (이름 중복 방지, URL 인코딩 불필요)
- 해당 러너의 제출 기록 목록
- 각 항목: 날짜, 거리, 시간, 금액, 상태 (승인 / 대기 / 거절)
- 승인된 기록만 금액 합산

### 3-4. 관리자 (`/admin`)
- 비밀번호 입력으로 진입 (비밀번호는 배포 전 Firestore 콘솔에서 직접 설정)
- **러너 등록:** 이름 + 토스 아이디 입력으로 러너 추가 가능
- 러너 명단에서 선택 → 해당 러너의 기록 목록 표시
- 각 기록에 승인 / 거절 버튼
  - 속도 기준(7~10분/km) 벗어난 기록은 경고 배지 표시 — 최종 판단은 스폰서가 직접
- 승인 시: 금액 확정 + 토스 딥링크 버튼 제공 (`toss.me/{tossId}/{금액}`)
- 전체 잔액 및 러너별 **승인 대기 중인 금액** 요약 (`runners.pendingAmount` 기준 — "아직 내가 확인 안 한 기록들")

---

## 4. 핵심 플로우

### 러너 제출 플로우
```
이름 선택 → 사진 업로드 → AI 자동 추출 → 확인 → 제출 → 승인 대기
```

### 스폰서 승인 플로우
```
비밀번호 진입 → 러너 선택 → 기록 확인 → 승인 → 딥링크로 송금
```

### 송금 딥링크
- **토스:** `https://toss.me/{tossId}/{금액}` — 러너의 tossId를 runners 컬렉션에 저장해두고 승인 시 자동 생성
- **카카오페이:** 공개 딥링크 포맷 없음 → 토스 우선 사용. 카카오페이 필요 시 스폰서가 별도 수동 처리
- 앱에서 자동 계산된 금액과 함께 링크 제공, 실제 송금은 스폰서가 직접 처리

## 5. 데이터 모델 (Firestore)

### `runners` 컬렉션
```
{
  id: string,
  name: string,           // 러너 이름
  tossId: string,         // 토스 아이디 (선택, 송금 딥링크용)
  totalKm: number,        // 승인된 총 km
  totalAmount: number,    // 승인된 총 금액 (원)
  pendingAmount: number   // 승인 대기 중인 금액 (제출 시 증가, 승인/거절 시 감소)
}
```

> 러너 7명 초기 등록은 관리자 화면 내 "러너 추가" 기능으로 처리.
> 스폰서가 이름과 토스 아이디를 입력해 등록.

### `submissions` 컬렉션
```
{
  id: string,
  runnerId: string,
  runnerName: string,
  imageUrl: string | null, // Firebase Storage URL (수동 입력 시 null)
  distanceKm: number,      // AI 추출 또는 수동 입력
  durationSec: number,     // 소요 시간 (초) — 표시 시 분:초로 변환
  paceMinPerKm: number,    // 페이스 (분/km) — 항상 계산됨 (null 없음)
  submittedAt: timestamp,
  status: 'pending' | 'approved' | 'rejected',
  approvedAt: timestamp | null,
  amount: number,          // 지급 금액 (distanceKm * 1000)
  memo: string             // 거절 사유 등 (선택)
}
```

### `config` 문서 (`settings/main`)
```
{
  totalBudget: 1000000,   // 총 자본금 (원)
  spentAmount: number,    // 승인된 총 금액 (승인 시 즉시 증가)
  adminPassword: string,  // 해시된 비밀번호
  ratePerKm: 1000,        // km당 지급 금액
  speedMinMinPerKm: 7,    // 속도 기준 최소 (분/km)
  speedMaxMinPerKm: 10    // 속도 기준 최대 (분/km)
}
```

### 예산 차감 정책
- `spentAmount`는 **승인 버튼 클릭 시 즉시 증가** (딥링크 클릭 여부와 무관)
  - 이유: 딥링크는 외부 앱으로 이동하므로 앱에서 송금 완료 여부 추적 불가
  - 승인 = 지급 약속 = 예산 차감
- **소진 판정:** `spentAmount >= totalBudget` 이면 신규 제출 차단
- 잔액 표시: `totalBudget - spentAmount`

## 6. AI 이미지 추출

- **모델:** OpenAI GPT-4o Vision
- **입력:** 러닝 앱 스크린샷 (Strava, Nike Run Club, 삼성 헬스 등)
- **추출 항목:** 거리(km), 소요 시간(초), 페이스(분/km)
- **처리 위치:** Next.js API Route (`/api/extract-run`) — API 키 서버 보관

### 이미지 업로드 파이프라인 (Flow B)
1. 클라이언트가 이미지 파일을 multipart로 `/api/extract-run`에 전송
2. 서버에서 GPT-4o Vision으로 정보 추출
3. 서버에서 Firebase Storage에 이미지 저장 (Firebase Admin SDK 사용)
4. 서버가 클라이언트에 추출 결과 + `imageUrl` 반환
- Firebase Storage 보안 규칙: 비인증 클라이언트 직접 업로드 불허 (서버만 업로드)

### 수동 입력 Fallback
- 추출 실패 시 수동 입력 폼 표시
- **필수 항목:** 거리(km), 소요 시간(분, 초) — 두 항목 모두 필수
- 페이스는 거리와 시간으로 자동 계산 (별도 입력 불필요, null 없음)
- 이 경우 `imageUrl`은 `null`로 저장

### 속도 기준 처리
- **제출 시:** 추출된 페이스가 7~10분/km 범위 밖이면 러너에게 경고 문구 표시 ("기준 속도를 벗어났습니다") — 제출 자체는 허용
- **관리자 화면:** 기준 벗어난 기록에 경고 배지(⚠️) 표시
- **페이스가 null인 경우** (수동 입력 시 시간 미입력 등): 경고 배지 미표시
- **최종 판단:** 스폰서가 직접 승인/거절 결정 (자동 거절 없음)

---

## 7. 관리자 인증

- **방식:** 서버 사이드 검증 — `/api/admin/verify` API Route에 비밀번호 POST
- 서버에서 해시 비교 후 성공 시 `adminToken` 쿠키(또는 세션) 발급
- `settings/main` 문서는 Firestore 보안 규칙으로 클라이언트 직접 읽기 차단
- 관리자 화면은 유효한 `adminToken` 없으면 진입 불가

- 러너가 스크린샷 올리면 3초 내 AI 추출 결과 표시
