# 단체 대회 버스·배번·기록확정 소개 페이지 설계

날짜: 2026-08-30
상태: **설계 확정 (구현 대기)**
관련: `_docs/handoff/2026-08-18-group-event-member-home.md`, `_docs/superpowers/specs/2026-08-13-group-event-admin-design.md`, `pamphlet.html`, `pamphlet-group-event.html`

## 목표

2026년 8월에 재설계된 단체 대회 기능(버스 탑승 → 배번 입력 → 총무 스크랩 → 회원 셀프 컨펌)을 소개하는
**상시 사용법 안내 페이지**를 회원용·총무용 2가지로 만든다. 철원 마라톤에서 처음 베타로 운영하며,
그 경험을 바탕으로 기능을 계속 확장/개선할 예정이다.

## 문체 원칙 (중요)

- 총무·회원 모두 **IT 업무에 익숙하지 않은 사람**이 읽는다고 가정하고 작성한다.
- "CTA", "API", "import", "쿼리 파라미터" 같은 개발 용어를 본문에 노출하지 않는다. 실제 화면에 보이는 말(예: "탑승 체크", "명단 올리기")로만 설명한다.
- 필드명(`source`/`sourceId`, `openLeg` 등)은 페이지 문구에 그대로 쓰지 않고, 사람이 읽는 말로 바꿔 쓴다. 이 스펙 문서에서도 개발 참고가 필요한 경우에만 코드 표기를 최소로 남기고, 실제 페이지 카피 후보는 평이한 말로 적는다.
- 섹션 제목도 괄호로 개발 메모("(CTA 대체 섹션)" 같은)를 달지 않고, 읽는 사람이 그대로 이해할 수 있는 제목으로 쓴다.

## 배포 방식 (사용자 확인 완료)

- 카톡방(회원 전체)에 **회원용** 페이지 URL 공유
- 총무님들께 (1:1 또는 총무방) **총무용** 페이지 URL 별도 전달
- 기존 팜플렛들과 동일하게, 앱 내 어디에도 링크되지 않는 **독립 공유용 랜딩 페이지**
- 총무용 페이지는 운영자 비밀번호(`dmc2008`)가 노출되므로 외부 공유 금지 경고 유지

## 파일 구조 (결정)

| 대상 | 파일 | 처리 방식 |
|---|---|---|
| 총무용 | `pamphlet-group-event.html` | **전체 재작성** (기존 2026-04-13 버전은 구 플로우 — 총무 일괄확정 중심이라 대체) |

`pamphlet.html`/`pamphlet-public.html`/`pamphlet-group-event.html`과 마찬가지로 다른 페이지에서 링크하지 않는다.

## 회원용 페이지 (`pamphlet-group-event-member.html`)

**스타일**: `pamphlet.html`과 동일한 모바일 우선 카드형(히어로 + 흰 카드 섹션 + CTA), 파란 그라디언트 계열.

**중요 제약**: `event-home.html`은 `?eventId=...`가 필요해 회원이 스스로 찾아 들어갈 수 있는
공개 목록 페이지가 없다. 따라서 이 페이지에는 **동작하는 단일 CTA 버튼을 두지 않는다**.

**갱신 노트 (2026-08-30, 사용자 확인)**: 위 제약은 "이 페이지가 어느 대회에도 종속되지 않는
상시 안내"라는 설계 의도를 지키기 위한 것이었다. 다만 **철원DMZ국제평화마라톤(2026-09-05, eventId
`evt_2026-09-05_23_dmz`)이 실제 첫 시범 운영 대회로 확정**되면서, "어떻게 시작하나요" 섹션 안에
그 대회로 바로 들어가는 실제 링크(회원 페이지 `event-home.html?eventId=evt_2026-09-05_23_dmz`,
총무 페이지 `event-admin.html?eventId=evt_2026-09-05_23_dmz`) 2개를 예외적으로 추가했다.
페이지 전체를 "철원 전용"으로 바꾸는 것은 아니고, QR 스캔이 주 진입로라는 설명은 그대로 유지하며
보조 링크만 문장 대신 클릭 가능한 형태로 바꾼 것이다. 다음 대회부터는 이 두 링크의 eventId를
갱신하거나, 시범 운영이 끝나면 다시 문장형 안내로 되돌릴 수 있다.

**진입 방식 (2026-08-30 갱신, 사용자 확인)**: 회원은 링크를 받아 들어가는 게 아니라,
**버스에 타서 자리에 앉은 뒤, 앞쪽 관광버스 TV에 크게 붙어있는 QR을 폰 카메라로 스캔**하는 것으로 시작한다.

**QR 위치·스캔 시점 (2026-08-30, 사용자 결정)**: 문이나 좌석이 아니라 **관광버스 앞쪽 TV에 크게** 붙인다.
스캔은 탑승 직후가 아니라 **자리에 앉은 뒤**가 좋다. 회원이 앉아서 편하게 찍을 수 있게 하려는 운영 선택이다.

- 총무가 `event-admin.html` 버스 패널에서 탑승 QR(`boarding.html?eventId=...` 인코딩, `api.qrserver.com`으로 생성)을
  내려받아 관광버스 앞쪽 TV에 크게 인쇄해 붙여둔다. 이 QR은 가는편·오는편 공통이다(연 상태는 총무가 서버에서 관리).
- QR을 찍으면 `boarding.html?eventId=...` → `event-home.html?eventId=...&board=1`로 자동 리다이렉트되고,
  닉네임이 저장돼 있으면(출석부 로그인 등) 곧바로 탑승 확인 화면이 뜬다.
- 탑승 체크를 마치면 배번 입력까지 **같은 화면 흐름 안에서 이어서** 진행된다(추가 QR·링크 불필요).
  탑승 완료 화면에는 "이어서 배번 입력" 보조 링크가 자동으로 뜬다.
  배번을 넣었다고 바로 기록이 뜨는 것은 아니다. 대회를 뛰고 난 뒤에 기록을 확인한다
  (사용자 요청, 2026-08-30: 배번 입력 직후 기록 확인이 이어지면 시간 순서가 전달되지 않음).
- `my-bib.html?eventId=...` 링크는 버스를 안 타는 회원이나, QR을 놓친 사람에게 총무가 개별로 안내하는 **보조 수단**일 뿐 주 진입로가 아니다.

### 섹션 구성

1. **히어로**
   - 타이틀: "단체 대회, 버스·배번·기록까지 폰 하나로"
   - 배지: "신기능 · 철원마라톤부터 시범 운영"
2. **왜 필요한가** (Before/After 대비 카드, `pamphlet-group-event.html` 구버전의 Before/After 패턴 재사용)
   - Before(실제 과거 방식, 사용자 확인): 총무가 버스 탑승 여부를 A4 용지에 손으로 체크하고, 대회 기록은 기록관이 이름으로 기록 사이트를 하나씩 검색해서 따로 정리
   - After: 자리에 앉아 QR 찍고 탑승 체크, 배번을 입력해두면 대회가 끝난 뒤 기록이 자동으로 나타나고 "맞다"고 확인만 하면 끝
3. **사용 흐름 6단계** (flow 컴포넌트, 가로 스텝) — **진입점을 QR 스캔으로 갱신, 사용자가 명시한 정확한 순서로 확정**

   사용자가 확인한 정확한 흐름: *"회원이 새벽에 버스 탑승 → 자리에 앉아 앞쪽 TV의 QR 촬영 → 단체 대회 페이지 랜딩 →
   (로그인 상태면) 바로 탑승 완료 체크 → 종목·배번 입력 / (로그인 안 된 상태면) 닉네임 선택 → 탑승 완료 체크 → 종목·배번 입력 → 대회 참가(경기 뛰기) → 대회 후 기록 확인"*

   **갱신 근거 (2026-08-30, 사용자 요청):** 배번 입력 다음에 바로 기록 확인이 오면, 배번을 넣은 뒤 바로 기록이 뜨는 것처럼 오해된다. 실제로는 배번 입력 → 대회 참가(경기 뛰기) → 대회가 끝난 뒤 기록 확인이다.

   1) 자리에 앉아 QR 스캔 *(앞쪽 관광버스 TV에 크게 붙어있는 QR을 폰 카메라로 찍기 → 랜딩)*
   2) 닉네임 선택 *(로그인/체크인 안 된 상태일 때만 뜨는 단계. 이미 출석부 앱에 로그인/체크인 되어 있으면 이 단계는 자동으로 건너뜀 — `EventMemberProfile`이 출석부와 같은 저장 정보를 공유해서 이름을 바로 알아봄. `resolveBoardingEntry`가 저장된 닉네임이 없을 때만 `list`(선택) 화면을 반환)*
   3) 탑승 완료 체크
   4) 종목·배번 입력 *(탑승 완료 화면에서 "이어서 배번 입력"으로 바로 이어짐, 별도 QR·링크 불필요)*
   5) 대회 참가 (경기 뛰기) *(앱 밖 단계. 배번 입력과 기록 확인 사이의 시간 순서를 분명히 하기 위해 추가)*
   6) 대회 후 기록 확인 → 완료 *("이 기록 맞아요?" 확인. 대회가 끝난 뒤라는 시점을 강조)*
4. **왜 배번을 입력해야 하나**
   - 동명이인이 있어도 정확히 내 기록을 찾을 수 있음 (이름만으로는 헷갈릴 수 있음)
   - 앞으로 배번으로 대회 중 실시간 기록(구간별 통과 시간 등)까지 확인할 수 있게 넓혀갈 계획임
5. **버스는 왕복 각각 체크**
   - 가는 편 탑승 체크와 오는 편 탑승 체크가 별개라는 점, 가는편·오는편 둘 다 체크해야 한다는 점만 강조 (홈 화면 "할 일" 카드 개념은 이후 변경으로 없어졌으므로 문구에서 제외 — 사용자 확인, 2026-08-30). **QR은 가는편·오는편 공통**이라 같은 QR을 돌아오는 버스에서도 다시 찍으면 됨
6. **어떻게 시작하나요**
   - "버스에 타서 자리에 앉으면, 앞쪽 관광버스 TV에 크게 붙어있는 QR 코드를 폰 카메라로 찍으면 시작됩니다"
   - QR을 놓쳤거나 배번을 나중에 따로 넣고 싶을 때는 아래 링크로 들어가면 됩니다
   - **(2026-08-30 갱신)** 위 갱신 노트대로, 철원 마라톤이 실제 시범 운영 대회로 확정되면서 이 보조 안내를
     문장이 아니라 실제 클릭 가능한 링크 2개(철원 회원 페이지 `event-home.html?eventId=evt_2026-09-05_23_dmz`,
     총무 페이지 `event-admin.html?eventId=evt_2026-09-05_23_dmz`)로 넣었다
7. **시범 운영 안내 박스**
   - "철원마라톤에서 처음 운영 중이라 화면이 계속 좋아질 예정이에요. 이상하거나 헷갈리는 부분은 총무에게 알려주세요"
8. **푸터** — 동탄 마라톤 클럽 © 2026

## 총무용 페이지 (`pamphlet-group-event.html` 갱신)

**스타일**: 기존 파일의 A4형 데스크톱 스타일(그라디언트 헤더 + 카드 + 표 + step 넘버링) 그대로 유지, 내용만 교체.

### 섹션 구성

1. **헤더** — 제목을 "단체 대회 버스·배번·기록 관리 가이드"로 갱신, "⚠️ 비밀번호 포함 - 외부 공유 금지" 배지 유지
2. **접근 정보**
   - `group.html` (대회 등록/목록) + 운영자 비밀번호 `dmc2008`
   - 대회별 운영 페이지는 `event-admin.html?eventId=...` (대회 등록 후 카드 클릭으로 진입)
   - 보조 경로 `group-detail.html?eventId=...` (일괄확정 등 갭 처리용, 표에 "보조"로 명시)
3. **개요 (Before/After)**
   - 기존 방식: 총무가 참가자를 등록하고, 대회 후 기록도 총무(또는 기록관)가 이름으로 하나씩 찾아서 확인·정리
   - 새 방식: 회원이 배번을 스스로 입력하고, 본인 기록도 스스로 확인·확정 → 총무는 대회 등록, 버스 관리, 기록 수집 실행만 하면 됨
4. **한 화면에서 순서대로 하는 일** (기존 step 넘버링 컴포넌트 재사용)
   1) **준비** — 대회 등록, 참가자 명단 올리기, 기록을 어디서 가져올지(사이트 이름과 대회 번호) 입력
   2) **버스** — 명단을 파일로 올리기, 가는편·오는편 중 지금 탑승 체크 받을 편 켜기, **탑승 QR을 내려받아 관광버스 앞쪽 TV에 크게 인쇄해 붙여두기**(가는편·오는편 공통 QR, 회원이 자리에 앉은 뒤 찍도록), 타는 장소 이름 정하기
   3) **배번** — 회원들이 배번을 얼마나 입력했는지 현황 확인 (입력 자체는 회원이 직접 함)
   4) **기록 수집** — 배번을 입력한 회원만 대상으로 기록 수집 시작/종료, 안 되는 사람은 따로 처리
5. **주의사항**
   - 회원은 카톡 링크가 아니라 **관광버스 앞쪽 TV에 크게 붙인 QR을 스캔**하는 것으로 시작함. QR을 안 붙이면 회원이 들어올 방법이 없으니, 출발 전에 꼭 인쇄해서 TV에 붙여둘 것
   - 배번을 입력하지 않은 참가자는 기록 수집 대상에서 빠짐(= 대회에 안 나간 것으로 처리됨)
   - 기록을 자동으로 가져올 수 있는 사이트는 스마트칩·오마이레이스·SPCT 세 곳뿐 (그 외 사이트는 아직 지원 안 함)
   - 기록 확정은 **회원이 스스로 확인하는 것이 기본 방법**이고, 총무가 대신 한꺼번에 확정하는 기능(옛 화면)은 어쩔 수 없을 때만 쓰는 보조 수단
   - 총무가 한꺼번에 확정하면, 이미 회원이 스스로 확인해둔 기록도 덮어써질 수 있으니 다시 확정할 때는 주의
6. **자주 묻는 질문**
   - Q. QR을 못 찍었거나 버스를 안 탄 회원은요? → "버스" 화면에서 탑승 링크를 복사해 개별로 보내주면 QR과 똑같이 들어갈 수 있어요
   - Q. QR은 어디에 붙이나요? → 버스 문이나 좌석이 아니라 관광버스 앞쪽 TV에 크게. 회원이 자리에 앉은 뒤에 편하게 찍으려는 선택
   - Q. 회원이 배번을 안 넣으면요? → 기록 수집 대상에서 빠지니, 총무님이 입력해달라고 알려주셔야 해요
   - Q. 회원이 본인 확인을 안 하면요? → 총무가 옛 화면(보조 기능)에서 대신 확정해줄 수 있어요
   - Q. 버스만 타고 대회는 안 뛰는 사람은요? → 버스 타는 명단과 대회 참가자 명단은 서로 다른 목록이라, 버스만 따로 등록할 수 있어요
7. **철원 베타 노트**
   - "이번 철원마라톤에서 처음 운영하며 기능을 계속 다듬을 예정입니다. 사용 중 불편한 점은 알려주세요"

## 스타일·컴포넌트 재사용 원칙

- 새 CSS/JS 프레임워크 도입 없음. 두 파일 모두 `pamphlet.html`/`pamphlet-group-event.html`의 기존 인라인 `<style>` 패턴을 그대로 복제해 독립적으로 유지한다(기존 팜플렛 관행과 동일 — 공유 스타일시트로 묶지 않음).
- 회원용 페이지는 `pamphlet.html`과 동일하게 `<link rel="icon">`, `og:title`/`og:description`/`og:image`/`og:url` 메타 태그를 유지해 카톡 공유 시 미리보기 이미지가 빠지지 않도록 한다.
- 새 API·백엔드 변경 없음. 정적 HTML 콘텐츠 작업만 해당.

## 테스트 계획

- 백엔드/데이터 변경이 없으므로 별도 API 테스트는 불필요.
- 두 파일 모두 유효한 HTML인지, 내부 링크(`event-admin.html`, `group.html`, `my-bib.html` 등)가 올바른 상대경로인지 스모크 확인.
