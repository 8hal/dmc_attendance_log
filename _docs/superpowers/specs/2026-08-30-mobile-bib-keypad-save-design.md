# 대회 홈 종목 먼저 · 배번 키패드 저장

**상태:** 리뷰 요청 (대화 2026-08-30, 플로우 정정)  
**대상 화면:** `event-home.html?eventId=evt_2026-09-05_23_dmz` (철원 DMZ 대회 홈)  
**범위:** `event-home.html` 프로필 섹션(`<section id="profileCard">` → `#profileBibForm`)이 배번·종목을 받을 때  
**관련:** `_docs/superpowers/specs/2026-08-23-event-member-day-ux-design.md`

`my-bib.html`은 레거시 단독 배번 페이지다. 이번 문의 대상이 아니고, 곧 없어질 예정이다.

`race_events.participants[].bib`를 쓰는 곳은 `update-bib` 액션 하나뿐이고, 그걸 호출하는 화면은 `event-home.html`과 `my-bib.html` 둘뿐이다. `event-home.html`의 `submitUpdateBib`는 이미 배번·종목이 둘 다 있어야 호출된다. 배번만 보내는 곳은 `my-bib.html`뿐이다. 그래서 `my-bib.html`이 없어지면, 이 화면만으로는 배번만 있고 종목이 없는 상태가 **새로** 생기지 않는다. 다만 그 페이지로 이미 저장된 기존 참가자 레코드는 남아 있을 수 있다 — 아래 "배번만 있음" 분기는 그 기존 데이터를 위한 방어 처리이고, 현재 활성 입력 경로는 아니다.

## 목표

프로필 섹션에서 **종목을 먼저** 고른다. 고르면 **그때 배번 칸**이 나오고, 숫자 키패드의 확인 키로 저장한다. 섹션 문구는 버스 탑승 여부와 무관하다.

지금처럼 배번 칸과 종목 칩을 한 화면에 동시에 두지 않는다. 키패드가 칩을 가리는 상태가 없어진다.

## 배경

지금 `#profileBibForm`은 배번 입력 + 종목 칩 + `저장`이 한 덩어리다. 배번 칸에 `inputmode="numeric"`만 있어서 안드로이드 키패드가 **이동**을 보여주고, 눌러도 `submitUpdateBib`가 안 된다.

문의 화면이 이 프로필 섹션이다. 안내 문구는 14px 회색(`#profilePrompt.today-desc`)이라 “지금 무엇을 고르라”가 잘 안 읽힌다.

## 결론

**같은 프로필 섹션 안에서 두 단계로 나눈다. 페이지를 나누지 않는다.**

1. 종목 — 칩만. 키패드 없음.
2. 배번 — 고른 종목이 남은 뒤 배번 칸이 나타남. 키패드 확인 = 저장.

OS 키패드 위에 우리 버튼을 올릴 수는 없다. `enterkeyhint="done"`으로 오른쪽 키를 제출로 만들고, form `submit` → `submitUpdateBib`에 연결한다. 그 키가 **완료/입력/이동** 중 무엇으로 보이든, 누르면 저장이면 된다.

## 단계

### 1) 종목

칩만 보인다. 배번 칸과 `저장`은 숨긴다. 자동 포커스 없음.

**문구 (잘 읽혀야 함)**

> 이번 대회에 어느 종목에 출전하나요?

탑승 여부·「배번 수정」과 관계없이 이 한 문장만 쓴다. `#profilePrompt`를 질문으로 쓴다. 18px 이상, 굵게, 본문색. 지금의 14px 회색 보조문이 아니다.

전체화면 `#boardDoneOverlay` (“버스 탑승 완료”)는 그대로 둔다. 프로필 섹션 문구와 섞지 않는다.

칩을 누르면 `selectedDistance`만 바꾸고 2단계로 간다. 이 시점에는 `update-bib`를 호출하지 않는다.

### 2) 배번

고른 종목 칩이 선택된 채로 남고, 그 아래 배번 칸이 나타난다.

**문구**

> 기록 자동 수집을 위해 배번을 입력해 주세요.

이 문구는 16px 본문색. 1단계 질문보다 한 단계 작게. 회색 보조문은 쓰지 않는다.

- 칩으로 방금 종목을 고른 직후에만 배번 칸을 포커스한다. 키패드가 뜬다.
- 참가자에 종목이 이미 있어 2단계로 바로 온 경우, 또는 「배번 수정」으로 온 경우에는 포커스하지 않는다. 칸을 탭하면 키패드가 뜬다.
- 칩은 그대로 보여 다른 종목으로 바꿀 수 있다. 바꿔도 2단계에 남는다. 선택 해제로 종목을 비우지 않는다.
- 배번 칸·`저장`은 `.hidden`으로 숨긴다. 노드를 제거하지 않는다.
- `저장` 버튼은 이 단계에서만 보인다 (키패드가 없는 기기·키패드를 닫은 뒤).

## 키패드 저장

- `#profileBib`에 `enterkeyhint="done"`. `inputmode="numeric"` 유지. `type="number"` 금지.
- `#profileBibForm`을 `<form id="profileBibForm">`으로 바꾼다. id는 유지.
- `submit`에서 `preventDefault` 후 `submitUpdateBib(activeIdentity)`.
- 칩·저장은 `type="button"`.
- 키패드 확인과 `Enter`는 form `submit` **한 경로**만. 별도 Enter 리스너 금지.
- IME `isComposing`이면 submit 무시.
- 일부 안드로이드는 키가 여전히 **이동**으로 보일 수 있다. 문구 변경은 성공 기준이 아니다.

## 저장 조건

기존 `submitUpdateBib` + `group-events` / `subAction=update-bib` (`bib`, `distance`). API 변경 없음.

| 단계 | 배번 | 종목 | 키패드 확인 / Enter / 저장 |
|------|------|------|------------------------------|
| 1 | (칸 없음) | 없음 | 해당 없음 |
| 2 | 있음 | 있음 | `update-bib` 한 번 |
| 2 | 없음 | 있음 | 토스트: 배번과 종목을 넣어 주세요. 저장 안 함 |
| 2 | 있음 | 없음 | 같은 토스트. 1단계로 되돌림 |

## 어디에 어떤 단계로 들어가나

| 상황 | 시작 단계 |
|------|-----------|
| 배번·종목 둘 다 없음 | 1 종목 |
| 종목만 있음 (로스터 등) | 2 배번. 칩 미리 선택. 포커스 없음 |
| 배번만 있음 (`my-bib.html` 제거 전 저장된 기존 레코드) | 1 종목. 배번 값은 칸에 채워 두고 칸은 숨김. 종목 고르면 2단계에서 보임 |
| 「배번 수정」/`아니에요` | 채워진 값 기준. 종목 있으면 2, 없으면 1. 포커스 없음 |

## 제외

- `my-bib.html`, `group-detail.html` 인라인 배번
- 종목/배번을 다른 페이지로 분리
- 신규 HTTP API
- OS 키패드 안에 커스텀 **저장** 키를 그리는 것 (불가능)
- 키패드 위 sticky 저장 바 (이번 범위 밖. 키패드 확인 + 섹션 `저장`으로 충분)
- 칩 탭 즉시 `update-bib`
- 종목 없이 배번만 저장
- 프로필 섹션의 `wait` / `pending` / `manual` / `confirmed` 상태
- `#boardDoneOverlay` 문구·타이밍 변경

## 검증

- 종목 없으면 배번 칸·`저장`이 DOM에서 안 보인다.
- 칩 클릭 후 배번 칸이 보이고, 그 클릭으로 포커스가 간다.
- 종목+배번 있는 2단계에서 `Enter` → `submitUpdateBib` **한 번**.
- 2단계에서 배번 비고 `Enter` → 저장 호출 없음, 기존 토스트.
- 1단계 문구는 항상 `이번 대회에 어느 종목에 출전하나요?`다. 탑승 여부로 바뀌지 않는다.
- 1단계 `#profilePrompt`가 질문 스타일(18px 이상, 굵게, 본문색)이다.
- `inputmode="numeric"`, `enterkeyhint="done"`이 있다.
- form `submit`이 페이지를 리로드하지 않는다.
- `#profileBibSave` 클릭 저장은 2단계에서 유지된다.

단계 판별은 `EventHomeAction` 헬퍼로 두고, 렌더러는 그 결과만 따른다. 브라우저 실기는 구현 후 해당 대회 홈에서 확인한다. 단위 테스트는 그 헬퍼와 `event-home-pick` 쪽 마크업·submit 가드를 잠근다.
