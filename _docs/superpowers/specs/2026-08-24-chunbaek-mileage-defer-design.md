# 춘백 마일리지 — S3 보류 결정

**작성일:** 2026-08-24  
**상태:** 시즌3 구현 안 함 (결정 확정)  
**관련:** [시즌3 PRD](./2026-07-12-chunbaek-season3-attendance-design.md) §4.2·4.3, [확정 사항](./2026-07-12-chunbaek-season3-confirmed-decisions.md)

이 문서는 구현 스펙이 아니다. 시즌3에서 하지 않기로 한 이유와, 다음 시즌에 다시 열 때 지켜야 할 전제만 적는다. **구현 계획(`writing-plans`)을 이 문서 뒤에 만들지 않는다.**

---

## 1. 결정

춘백 시즌3에서 **월 마일리지 목표·누적 공개·가민 연동·러닝 스크린샷 입력**을 하지 않는다.

출석(오늘 / 내 100일 주간 / 팀 출석률)만 유지한다.

---

## 2. 왜 보류하는가

검토 목적: 가민 아이디·비밀번호를 넣고 월 마일리지를 보여 주면, 팀에 공개된 목표가 훈련을 끌어당길 수 있는가.

결론: **가치는 공개 목표에 있고, 시즌3에서 그 가치를 살릴 입력 수단이 없다.**

| 안 | 왜 시즌3에서 탈락 |
|----|-------------------|
| 가민 아이디·비밀번호를 춘백 서버에 저장 | 건강·위치 계정 유출 범위. MFA. 비공식 로그인 변경. Cloud Functions에 둘 수 없음 |
| 일자마다 러닝 앱 스크린샷 → OCR → 합산 | 출석 사진과 별도 공수. 가민이 이미 월 합계를 보여 줌. 공수 > 공개 이득 |
| 주 1회 월 합계 스크린샷 | 공수는 줄지만, 매일 신선한 공개 보드가 되지는 않음. 어중간하면 출석만 있는 지금보다 못할 수 있음 |
| 출석 슬롯에 km 붙이기 | 출석 안 한 날에도 운동함. 휴무·예외·하루 두 번과 충돌 |

가민·스트라바·코로스 앱이 개인 월 합계는 이미 잘한다. 춘백이 같은 숫자를 다시 보여 주는 것만으로는 효용이 약하다. 남는 가치는 **월 목표 선언 + 오늘까지 누적이 팀에 보이는 것**뿐인데, 그 보드가 매일 갱신되려면 입력이 거의 공짜여야 한다. 시즌3 스택으로는 그 공짜 경로가 없다.

---

## 3. 나중에 다시 열 때 유지할 전제

재검토 시에도 아래는 뒤집지 않는다. 뒤집으면 이 문서를 먼저 개정한다.

1. **출석 ≠ 마일리지.** 슬롯 출석과 월 km는 다른 기록이다. `chunbaek_attendance`에 km를 넣지 않는다. `내 100일` 일자 칸을 마일리지 달력으로 쓰지 않는다.
2. **춘백 서버에 워치 계정 비밀번호를 저장하지 않는다.** 로그인 순간에도 비밀번호를 Firestore에 남기지 않는다.
3. **출석하기 CTA에 마일리지 입력을 붙이지 않는다.** 핵심 루프(10초 출석)를 무겁게 만들지 않는다.
4. **수동 입력을 매일 전제로 두지 않는다.** 자동이 아니면 매일일 수 없다. 매일 최신이 실패 조건이면 자동 연동이 준비된 뒤에만 만든다.
5. **목표 km는 공개가 기본이다.** 몸무게와 반대로, 보여 주려고 만드는 숫자다.
6. **시즌3 출석 앱에 신규 마일리지 API를 넣지 않는다.** 재개 시에만 유사 API 전수 조사 + 필요성 문서 + 사용자 승인을 다시 한다.

---

## 4. 다음 후보: 가민·코로스 MCP

다음 시즌(또는 별도 도구)에서 다시 본다면, **회원 수동 스크린샷보다 워치 브랜드 MCP로 월 러닝 km를 읽는 안**을 먼저 본다.

### 4.1 왜 MCP인가

- 회원은 춘백에 숫자를 다시 치지 않는다.
- 코로스는 공식 MCP(`https://mcp.coros.com/mcp`)가 있다. 계정 권한 동의 후 활동 목록(날짜·스포츠·거리·시간)을 읽는다. 2026-05 기준 read-only, 워크아웃 리스트에 거리가 포함된다.
- 가민은 공식 MCP가 없다. 커뮤니티 MCP(`garmin_mcp` 등)는 `python-garminconnect`로 Connect에 붙고, 대개 **로컬 stdio + 본인 계정 토큰**이다. 멀티유저 서버에 비밀번호를 넣는 용도가 아니다.

### 4.2 MCP가 해결하지 않는 것

MCP는 AI 클라이언트가 **한 계정**의 데이터를 읽게 하는 프로토콜이다. 춘백 팀 보드(참가자 ~40명의 `이번 달 km`)의 데이터 소스가 바로 되지는 않는다.

| 쓰임 | 맞는가 | 이유 |
|------|--------|------|
| 운영자/코치가 Cursor·Claude에서 본인 가민·코로스를 물어보기 | 맞음 | 1계정 ↔ 1 MCP |
| 참가자가 각자 AI에 워치를 연결해 개인 코칭 | 맞음 (춘백 앱 밖) | 팀 공개 보드와는 별개 |
| Cloud Functions가 40명 월 km를 매일 모아 팀에 표시 | 아직 아님 | 가민 비공식 MCP는 계정 비밀번호/토큰을 서버에 두는 문제가 남음. 코로스 공식 MCP도 **참가자별 OAuth·토큰 보관·일괄 조회**를 춘백 백엔드에 새로 설계해야 함 |

재개 조건(모두 필요):

- 코로스: 공식 MCP 또는 공식 API로 **참가자 동의 후 거리만** 서버가 읽을 수 있는가. 비밀번호 저장 없음.
- 가민: 공식 Health API / 공식 MCP가 생겼거나, 비밀번호 없이 토큰만으로 멀티유저가 가능한가. 커뮤니티 MCP를 Functions에 심는 것은 기본 거절.
- 입력 공수: 연결 1회 이후 회원 일일 조작 0.
- 제품: 월 목표 선언 + 팀 공개 누적. 출석 슬롯과 분리.

이 조건이 안 되면 다시 보류한다. 스크린샷 OCR·일자 칸 채우기로 우회하지 않는다.

### 4.3 범위 밖 (YAGNI)

- 페이스·심박·수면·GPS 경로를 춘백에 저장
- 스트라바 연동 (요청된 후보가 가민·코로스 MCP)
- 시즌3 중 파일럿 코드, 숨은 탭, 실험 API

---

## 5. 시즌3에서 하지 않는 일

- 신규 Cloud Function / `chunbaek` action
- Firestore 마일리지 필드, 월 목표 필드
- `내 100일` 월간 탭을 마일리지용으로 추가
- 가민·코로스 라이브러리를 `functions/`에 추가
- OCR·Vision 파이프라인

PRD Phase 2「슬롯에 마일리지 필드」도 이 결정과 충돌하면 **슬롯 필드 안은 쓰지 않는다.** 마일리지를 다시 할 때는 출석 슬롯 밖 모델로 설계한다.
