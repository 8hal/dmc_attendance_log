> **다음 태그:** 배포가 성공한 뒤에만 `v0.21.0`  
> **앱 버전:** 응원 화면 `<meta name="app-version" content="0.21.0">`. 춘백 앱 버전은 `chunbaek/VERSION` `0.3.0` 그대로다.

MINOR 버전이다. 응원 보드에 레디샷이 생기고, `v0.20.1` 이후 대회 중에 고친 실시간 응원(칩 출발·칩 페이스·도착 예상·완주 정렬·구간 표)이 포함된다. `main`에 있던 춘백 시즌 성과·팀 명단도 같이 들어 있다. 스키마는 참가자 문서에 `readyShotUrl`이 추가되는 수준이고, 기존 배번 저장은 그대로다.

## 배포하지 않는 조건

- `scripts/pre-deploy-test.sh` 실패
- 배번만 저장하는 기존 흐름이 깨짐
- 춘백 `ping` 또는 성과 페이지가 빠짐
- Storage 규칙을 올리지 않은 채 레디샷만 연 경우 (사진은 저장돼도 링크 보유자가 열지 못할 수 있음)

## 배포 체크리스트

배포는 사람이 요청한 뒤에, 아래 순서로 한다. GitHub Actions를 이 준비 커밋만으로 실행하지 않는다.

```bash
# 1. 테스트
npm run test:cheer
npm run test:group-scrape-bib
node --test scripts/test/chunbaek-*.test.js
bash scripts/pre-deploy-test.sh

# 2. 백업
cd functions && node ../scripts/backup-firestore.js && cd ..

# 3. 커밋이 원격에 있는지 확인한 뒤 배포
# functions-all 은 스케줄 함수까지 올린다. Cloud Scheduler Admin 권한이 필요하다.
# 권한이 없으면 functions:race (응원·배번 API)만 올리고, 춘백을 같이 올릴 때는 functions:chunbaek 를 포함한다.
firebase deploy --only functions --project dmc-attendance
firebase deploy --only hosting --project dmc-attendance

# 4. Storage. Actions 워크플로(functions-all, hosting)는 storage 규칙을 배포하지 않는다.
firebase deploy --only storage --project dmc-attendance
```

GitHub Actions로 올릴 때:

| 단계 | 워크플로 | 입력 |
|---|---|---|
| Functions | Deploy DMC Attendance (Firebase) | `functions-all` |
| Hosting | 같은 워크플로 | `hosting` |
| Storage | 워크플로에 없음 | 로컬 `firebase deploy --only storage` |

`functions-all`이 스케줄러 권한으로 실패하면 `functions:race,functions:chunbaek` 후 hosting, 그리고 storage.

### Storage 설정

`storage.rules`에 경로를 추가했다.

- 경로: `cheer/ready-shots/{eventId}/{fileName}`
- 읽기: `.jpg` 허용 (다운로드 토큰 URL과 함께, 응원 보드 링크를 가진 사람이 사진을 본다)
- 쓰기: 거부. 업로드는 Functions Admin SDK만 한다.
- 참가자 필드: `race_events.participants[].readyShotUrl`
- 한 참가자당 파일 하나. 다시 올리면 같은 경로를 덮어쓴다.
- 최대 2MB, JPEG(`FF D8 FF`)만 받는다.

버킷을 새로 만들 필요는 없다. 규칙 배포가 필요하다.

### 배포 후 확인

```bash
curl -sI "https://dmc-attendance.web.app/lab/cheer/bib.html?eventId=evt_2026-10-25_2026" | head -n 5
curl -sS "https://dmc-attendance.web.app/cheer/bib.html?eventId=evt_2026-10-25_2026" | grep -E 'app-version|레디샷|누구나 사진을 볼 수 있어요'
curl -sS "https://dmc-attendance.web.app/cheer/index.html?eventId=evt_2026-10-25_2026" | grep -E 'shotLightbox|app-version'
curl -sS "https://dmc-attendance.web.app/api/chunbaek?action=ping"
curl -sS "https://dmc-attendance.web.app/chunbaek/" | grep 'app-version'
```

- 운영: `event-admin` 배번 칸에서 배번·레디샷 링크와 응원 보드 링크를 복사한다. 조·출발 시각은 `cheer/waves.html`에서 저장한다.
- 예전 `lab/cheer/*.html?eventId=` 는 `cheer/` 로 301 되고 쿼리는 유지된다.
- 응원: 보드에서 선수 상세를 열고, 레디샷이 있으면 닉네임 아래에 보이고 누르면 커진다. 없으면 그 칸이 없다.
- 선수: 배번 페이지에서 사진을 올리고, 읽은 배번을 고친 뒤 저장한다. 숫자를 못 읽어도 저장된다.
- 사진을 다시 올리면 상세의 사진이 바뀐다.
- 명단을 `group.html`에서 다시 저장해도 `readyShotUrl`이 남는다.
