# 춘백 100일 훈련 가이드 위키 디자인

> 작성일: 2026-07-27  
> 상태: 초안 (브레인스토밍 합의 반영)  
> 관련: handoff `2026_마라톤_100일_수준별_훈련_가이드`, `_docs/design/chunbaek-kakao-guide-page.md`, `chunbaek/exception-guide.html`

## 1. 문제와 목표

### 문제

- 기존 초안(DOCX/PDF, 43쪽)은 **수준별 용량 차등**(완주형·향상형·기록형·상급형)과 **페이스·거리 처방표** 중심이다.
- 실제 춘백 운영은 **요일별 훈련이 고정**되고, 팀은 **페이스만 소폭 다르게** 달린다.
- 참가자 목표도 4수준이 아니라 **서브3 / 싱글 / 330+첫풀**에 가깝게 분포한다.
- 긴 PDF는 카톡·모바일에서 **발췌독**하기 어렵다.

### 목표

로그인 없이 카톡으로 공유 가능한 **정적 멀티페이지 위키**를 만들고, 춘백 앱에서는 허브로 링크만 건다.

성공 기준:

1. 허브 + 주제 7개가 `/chunbaek/guide/` 아래에 열려 카톡·모바일에서 읽힌다.
2. 각 주제 글에서 **이전 / 목차 / 다음**으로 막힘 없이 이동한다.
3. 본문은 MJ 일지 사례 + 조사 근거로 **생동감** 있게 읽히고, 페이스·거리 **처방표는 넣지 않는다**.
4. 글마다(필요한 만큼) **서브3 / 싱글 / 330+첫풀** 읽는 포인트가 있다(유연한 B).

실패·롤백 기준:

- 카톡 인앱에서 레이아웃이 깨지거나 네비가 동작하지 않음
- 수준별 처방표·희망기록만으로 수준을 올리는 안내가 다시 들어감

### URL

| 순서 | 파일 | 제목(가칭) |
|------|------|------------|
| 허브 | `/chunbaek/guide/index.html` | 읽는 법 · 세 구간 · 목차 |
| 1 | `week.html` | 우리 주가 돌아가는 방식 |
| 2 | `long-run.html` | 장거리 |
| 3 | `quality.html` | 품질주 |
| 4 | `summer.html` | 여름철 |
| 5 | `pain.html` | 통증·피로 |
| 6 | `missed.html` | 놓친 날·실패한 날 |
| 7 | `taper-race.html` | 마지막 구간·대회 주 |

고정 읽기 순서: 허브 → 1→…→7.

### 네비게이션

각 주제 페이지:

- **상단**: `목차` 링크 + 위치 표시 (`3 / 7`)
- **하단**: `이전` | `목차로` | `다음`
  - 1번 글의 이전 = 허브
  - 7번 글의 다음 = 없음 (대신 목차 / 앱 CTA)
- 허브: 카드형 목차(제목 + 한 줄 요약) + 「첫 글 읽기」 CTA → `week.html`

의도적으로 안 함(v1): 검색, 태그, 로그인, PDF 강제 다운로드, 댓글.

### 앱 연결

- 위키 허브·각 글(또는 허브만 — 구현 시 허브 필수, 글은 하단 보조 CTA 허용)에서 **CTA 하나**: `춘백 앱으로` → `/chunbaek/#/today` (시즌 중 기본 홈). 프로필 미완이면 앱 기존 온보딩 동작에 맡긴다.
- 앱 `#/me`(나 탭)에 **훈련 가이드** 텍스트 링크 1개 → `/chunbaek/guide/`  
  (홈에 두면 출석 CTA와 경쟁하므로 v1은 나 탭)

## 4. 페이지 골격 · 시각

카카오 안내 패턴(`chunbaek-kakao-guide-page.md`, `exception-guide.html`)을 **위키용으로 확장**한다. 짧은 스텝 안내가 아니라 **본문 서사**가 중심이다.

### 공통

- `tokens.css` + Noto Sans KR
- `.page` max-width **480px**
- 브랜드 오렌지 헤더(eyebrow `춘백 S3` / 제목 / 한 줄 보조)
- 카카오 인앱 배너(UA `KAKAOTALK`일 때만)
- `theme-color #ff3214`, `viewport-fit=cover`
- 푸터: `동마클 · 춘백 S3`

### 허브

1. 헤더
2. 카카오 배너
3. 이 가이드가 전제하는 현실(요일 고정 · 해석이 다름) — 짧게
4. 세 구간 설명(서브3 / 싱글 / 330+첫풀) — 희망 기록이 아니라 **지금 목표 구간으로 읽기**
5. 목차 카드 7개
6. CTA: 첫 글 / 앱으로

### 주제 글

1. 헤더 + 상단 네비(목차 · n/7)
2. 카카오 배너
3. **리드** — 장면이나 질문으로 시작(생동감)
4. **본문** — 짧은 절, 사례 상자(MJ 재서술), 필요할 때만 불릿
5. **세 구간 포인트** (유연한 B)
   - 강하게: 장거리, 품질주, 테이퍼·대회
   - 약하게(또는 한 블록으로 합침): 여름, 통증, 놓친 날
   - 주간 루틴: 해석 차이만 짧게
   - 각 포인트 **2~4줄**, 페이스 숫자 나열 금지(예시로 MJ가 겪은 페이스를 이야기로 쓰는 것은 허용)
6. 하단 네비(이전 · 목차 · 다음) + 앱 CTA

시각: 본문 카드는 흰/연회색, 오렌지는 헤더·네비 강조·구간 라벨 정도. 플로팅 뱃지·통계 스트립·이모지 과다 금지.

## 5. 콘텐츠 원칙

1. **같은 훈련, 다른 렌즈** — 요일 세션을 전제로 쓰고, 수준별 거리표를 다시 만들지 않는다.
2. **처방 금지, 판단 허용** — 「몇 분 페이스로 ○km」표 대신 「몸이 이렇게 말했을 때 줄였다/유지했다」.
3. **MJ 일지는 따라 할 표가 아니라 사례** — 극단 마일리지·통증 속 강행·과도한 제한을 권장으로 바꾸지 않는다(handoff 주의사항 유지).
4. **의료 대체 아님** — 중단·상담 기준은 단정 진단처럼 쓰지 않는다.
5. **연구 근거** — 본문 흐름을 깨지 않게 짧은 팁; 필요 시 `[n]` 각주. handoff 참고문헌 9종을 재사용 가능하나 v1에서 장황한 「참고 자료」 전용 페이지는 두지 않는다.
6. **초안 DOCX** — 내용 재료·구조 참고. 위키가 SSOT가 되면 DOCX는 아카이브. 위키에 수준 체계(완주형 등)를 이식하지 않는다.

### 주제별 역할 (품질 체크 통과분)

| 글 | 역할 | 구간 포인트 세기 |
|----|------|------------------|
| 주간 | 현실 SSOT — 요일이 같고 해석이 다름 | 약 |
| 장거리 | 버티기·줄이기·회복 판단 | 강 |
| 품질주 | 인터벌·빌드업·템포를 이야기로 | 강 |
| 여름 | 더위·RPE·생존 | 약~중 |
| 통증 | 언제 줄이고 멈추는지 | 약~중 |
| 놓친 날 | 결손→다음 주 설계 | 약 |
| 테이퍼·대회 | A/B/C, 당일 전환 | 강 |

### v1에서 명시적 보류

체중·영양 전용 장, 중간점검 대회 장, 대회 후 평가 장, 진단 설문, 14주 수준별 예시 부록, 검색/CMS.

## 6. 기술 구성

### 파일

```
chunbaek/guide/
  index.html
  week.html
  long-run.html
  quality.html
  summer.html
  pain.html
  missed.html
  taper-race.html
  guide.css          # 위키 전용 (tokens 위 확장: 본문, 네비, 구간 포인트)
  guide-nav.js       # 선택: 순서 배열·이전/다음 링크 주입 (복제 실수 방지)
```

- 스타일: `../css/tokens.css` + `guide.css`
- 네비 순서 SSOT는 `guide-nav.js`의 배열 한곳 (또는 각 HTML에 동일 링크를 수동 — v1은 **JS 주입 권장**으로 링크 깨짐 방지)
- 신규 Cloud Functions / Firestore 스키마 **없음** (정적 호스팅만)
- PWA SW 캐시 목록에 guide 경로를 넣을지는 구현 계획에서 결정. 넣지 않아도 동작; 넣으면 오프라인 읽기 가능하나 v1 필수는 아님

### 공통 마크업 규약

- 구간 포인트 컨테이너: `.band-notes` + `.band-note[data-band="sub3|single|330"]`
- 네비: `.guide-nav` / `.guide-nav__prev` / `.guide-nav__toc` / `.guide-nav__next`
- 사례: `.guide-story` (MJ 재서술)

### 테스트 (계획 단계로 넘길 항목)

- 허브·7글 HTTP 200 (pre-deploy 또는 스모크)
- 각 글에서 prev/next/toc href가 순서와 일치
- 카카오 배너 토글 스크립트 존재
- 앱 나 탭에 guide 링크 존재(셀렉터/문자열)

## 7. 구현 범위 경계

| 포함 | 제외 |
|------|------|
| `chunbaek/guide/*` 정적 페이지 | Functions API |

| 카톡 공유 가능 공개 URL | DOCX/PDF 자동 생성 파이프라인 |

## 8. 리스크

| 리스크 | 완화 |
|--------|------|
| 긴 본문이 카톡 인앱에서 불편 | 짧은 절 + 주제 분리 + 이전/다음; 카카오 배너로 외부 브라우저 유도 |
| 구간 포인트가 처방표로 변질 | 리뷰 체크: 숫자 표·km 처방 유무 |
| MJ 사례가 흉내 훈련으로 읽힘 | 허브·각 글에 「사례이지 따라 하기 표가 아님」 한 줄 |
| HTML 복제로 네비 불일치 | `guide-nav.js` 단일 순서 배열 |

## 9. 열린 결정 (플랜에서 확정해도 됨)

- 앱 CTA 해시: 기본 `#/today` (본 스펙 권장). `#/me`만 쓸지는 플랜 시 한 줄 확인.
- Service Worker에 guide 캐시 포함 여부: 기본 **미포함**(YAGNI).
- 원고 1차 작성 언어/분량: 주제당 화면 스크롤 약 1.5~3화면(모바일) 목표.
